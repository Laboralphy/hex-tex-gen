# hex-tex-gen

Procedural generator of Hexen/Doom-like 2D bitmap textures: a platform-neutral TypeScript
library (`@laboralphy/hex-tex-gen`) and a CLI writing PNG files. User documentation lives in
`documentation/` (start with `documentation/concepts.md`).

## Getting started on a machine

```sh
git pull && npm ci          # always npm ci after a pull: dependencies change (zod, algorithms...)
npm run check               # typecheck, lint, format check, tests, build: the CI and release gate
npm run cli -- render examples/mossy-castle-wall.json -o /tmp/wall.png   # CLI from source
```

## Commands

| Command                              | Purpose                                                         |
| ------------------------------------ | --------------------------------------------------------------- |
| `npm test`                           | vitest, including the golden tests                              |
| `npx vitest run -u`                  | accept intended visual changes (updates golden snapshots)       |
| `npm run schemas`                    | regenerate `schemas/*.schema.json` from the Zod schemas         |
| `npm run docs`                       | regenerate `documentation/templates/*`, reference pages, images |
| `npm run lint:fix`, `npm run format` | fix lint and formatting                                         |

After changing any parameter schema (a default, a description, a new parameter or
template), run `npm run schemas && npm run docs`: tests fail when generated files are stale.
Files marked `generated by "npm run docs"` are never edited by hand.

## Layout

- `src/core/`: platform-neutral building blocks: `Texture` (RGBA, wrapping coordinates),
  `hash.ts` (position-based randomness), `math.ts` (`mod`, `clamp`, `firstPixel`...),
  `palette.ts`, `schema.ts` (Zod helpers: `size`, `range`, `ratio`, `color`, `palette`,
  `ageParam`, `shadowGroup`, `FROM_AGE`), `age.ts` (age curves), `object-fusion/` (deep merge).
- `src/generators/`: one file per template, registered in `generators/index.ts`, built with
  `defineGenerator` (`define.ts`). Every template has a `category` (`types.ts`): `surface`
  for wall textures, `ground` for floor and ceiling materials, else the ambiance of a
  decoration (`natural`, `civilized`, `dungeon`, `architecture`). `documentation/catalog.md` lists them by category, with their examples
  and ideas of patches still to make: the ideas live in `CATALOG` in `scripts/docs.ts`.
  - `ashlar/`: the ashlar template and the wall machinery shared by `bricks`, `fieldstone`,
    `metal` and `stoneslab`: wall schema, layout, wear, masonry, render passes (cracks,
    stains, moss growth). `ashlar/index.ts` re-exports it.
  - `common/`: pieces shared by several templates (palettes, metal weathering).
- `src/compose/`: texture and patch files: `extends`, placements, anchors, validation. Files
  are read through a `Loader`; the library never touches the file system.
- `src/themes/`: texture sets from one seed (`generateSet`): an ambiance (`ambiances/`)
  draws a theme, recipes (`recipes/`) build texture definitions on it. Theme salts live in
  `themes/salts.ts` and follow the same never-renumber rule.
- `src/cli/`: the CLI and its Node loader; `src/schemas.ts`: JSON Schema export.
- `scripts/`: docs and schema generators. `examples/`: texture and patch files, all covered
  by the golden tests.

## Design rules

- **Own size, layout and detail.** Every template has an own `size`. A patch placed at
  another size is regenerated, never stretched. Layout values (`.meta(LAYOUT)`) are pixels
  at own size and scale; detail values (`.meta(DETAIL)`) are real pixels and do not.
- **Position-based randomness.** Use `hash(seed, SALT_X, row, col, ...)`, one salt constant
  per kind of decision, never a sequential generator: the same seed gives the same stones
  at any size. Seed noises with `hashSeed`. Never renumber existing salts: it changes every
  render.
- **Everything tiles.** Wrap coordinates with `mod`, use periodic `FractalNoise`.
- **Age.** Wear parameters are optional; unset ones derive from `age` (0 new, 0.3 default,
  1 ruined) with `atAge` curves. Explicit values always win.
- **Schemas.** `z.strictObject`, every parameter has `.default()` and `.describe()`, nested
  groups end with `.prefault({})`.
- **Overlays** (`overlay: true`) are transparent by design and laid over walls. Effects such
  as moss must follow the stone layout (anchors, or the wall's own `moss` group), never a
  second translucent wall.

## Code conventions

- One class per file most of the time; split large modules into a folder of sub-modules
  with an `index.ts` re-exporting them (see `generators/ashlar/`).
- **No duplicated helpers.** Look in `src/core/` and `src/generators/common/` before writing
  one; shared code goes there and is imported.
- Match the surrounding style: 4-space indent, single quotes, 100 columns (Prettier), doc
  comments on exported symbols, imports sorted by path (packages, then `../`, then `./`).
- Public API: everything exported from `src/index.ts`.

## Golden tests

`tests/golden.spec.ts` renders every example texture and every template at its defaults,
and snapshots a SHA-256 of the pixels. A failure means a visual change: render the example,
look at it, then accept with `npx vitest run -u` if intended. Refactors must keep every
hash unchanged.
